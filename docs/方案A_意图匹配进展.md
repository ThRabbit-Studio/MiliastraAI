## 设计（为什么是这个结构）

```
玩家打拼音 -> 已有 IME 出中文 -> 编码器 -> 64 维向量
                                          |
                            与答案池各主题向量比余弦相似度
                                          |
                              取最相近主题的答句 -> 逐字显示
```

编码器刻意做成「**查表 + 平均 + 一次 64×64 矩阵乘**」：
- Lua 侧每字约 130 次乘加，30 字输入不到 4000 次 —— 实机远低于 1ms；
- 双嵌入表（汉字 + 拼音音节）：字库外的字按**同音**归位，自带同音字泛化。

## ⚠ 已知缺陷（必须在接入 Lua 前修掉）

1. **输入词表太小**：实测只用到 226 个汉字 / 151 个音节。
   原因是答案池的问法高度模板化，用字集中。
   → 应改为固定使用**全字库 3000 字 + 412 音节**，否则遇到没见过的字就没有嵌入。

2. **loss 0.0007 是过拟合假象**：
   训练时主题向量是由**同一批种子问法**现算现用的，而评估也在这批上，
   等于自己考自己。**必须做留出集评估**（拆一部分问法不参与训练）。

3. **参数量与「1M」不符**：当前只有 **27,224** 参数。
   按缺陷 1 改成 3000 字 × d_char + 412 音节 × d_syl 后，
   取 d_char=192 / d_syl=96 约为 **53 万**，取 d_char=256 / d_syl=128 约为 **77 万**。
   这才是与「1M 以内」相称的规模。

4. **尚未接入 Lua**：`main.lua` 仍走原来的字面重合匹配（F1）。
   接入需要：导出 int8 量化权重 + Lua 侧实现编码与相似度检索 + 校验一致性。
